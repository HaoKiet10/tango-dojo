# Grammar Deck Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Add a third practice deck, Ngữ pháp, to Tango Dojo. It has about 150 N5–N3 patterns, two JLPT-style modes (Chọn ngữ pháp, Sắp xếp câu), a meaning quiz and a browsable Ngữ pháp tab.

**Architecture:**
- **Data:** patterns live in `src/data/grammar.ts` and become `Item`s with `deck: "grammar"` and an attached `grammar` object. The existing picker, progress, settings, Mixed mode and answer panel work unchanged on them.
- **Modes:** two new mode components plug into `PracticePage`'s `MODES` map. `availableModes(deck)` becomes the single source for which modes a deck allows.
- **Page:** a new route and page provide the reference list.

**Tech Stack:** Vite, React 19, TypeScript, Tailwind v4, Vitest + Testing Library, Playwright.

**Spec:** `docs/superpowers/specs/2026-11-07-grammar-design.md`

## Global Constraints

- **Language:** UI text is Vietnamese + Japanese only (no English). Meanings and notes are in Vietnamese.
- **No auto-advance:** after an answer the panel waits for Next, and Next ignores presses for 300 ms. That's existing behaviour, so don't bypass it.
- **Mobile first:**
  - no horizontal scroll at 360px
  - tap targets at least 44px (`min-h-11`)
  - the phone tab bar holds 4 tabs
- **Colour:** colour only carries meaning (positive/negative/late tokens). No new palette.
- **Labels:**
  - deck: `grammar: { full: "Ngữ pháp 文法", short: "Ngữ pháp" }`
  - mode `grammar`: `{ vi: "Chọn ngữ pháp", ja: "文法形式" }`
  - mode `order`: `{ vi: "Sắp xếp câu", ja: "並べ替え" }`
- **Disabled reasons:**
  - `GRAMMAR_ONLY_REASON = "Chỉ dùng cho ngữ pháp"`
  - `NOT_GRAMMAR_REASON = "Không dùng cho ngữ pháp"`
- **Progress ids:** `"g:" + grammar.id`
- **Before each push:** `npm run check` (typecheck, lint, unit tests) and `npm run e2e` must pass. Push straight to main.

## Review Focus

1. **Saved settings from before grammar existed** load unchanged. A stored `deck: "grammar"` with mode `type` falls back to `mixed`, and is never thrown away as invalid. Test: Task 1, `loadSettings` and `fit`.
2. **An `order` question whose pieces repeat** (e.g. two `に` pieces) is marked right whenever the joined text matches, even if the identical pieces were tapped in swapped places. Test: Task 4.
3. **A grammar question where a look-alike pattern has the same `answer` string** never shows that string twice or marks the real answer wrong. Test: Task 2.
4. **Searching with or without Vietnamese accents** ("vua" finds "vừa … vừa …") and with the 〜 omitted ("ながら" finds "〜ながら"). Test: Task 6.
5. **Switching deck to grammar mid-session while on Gõ cách đọc** lands on Hỗn hợp, never on an empty or crashing question. Test: Task 1, settings test.

### Task 2: Grammar data checks and question building

**Files:**
- Modify: `src/data/data.test.ts`
- Modify: `src/lib/question.ts`
- Test: `src/lib/question.test.ts`

**Interfaces:**
- **Consumes:** `GRAMMAR`, `Item.grammar` (Task 1).
- **Produces:**
  - `Question.example?: 0 | 1`.
  - `buildQuestion("grammar")` returns `{ mode, items:[it], example, options: string[4], answer }`.
  - `buildQuestion("order")` returns `{ mode, items:[it], example, tiles: string[] }`.
  - `fullSentence(ex: GrammarExample): string` (exported from `question.ts`) returns `ja` with ＿＿ replaced by `answer`.
  - `buildQuestion("choice")` for a grammar item picks kind `meaning` or `prompt` with equal odds.

- [ ] **Step 1: Write the failing data tests** (in `data.test.ts`, a `describe("grammar")` block):
  - ids unique and matching `/^[a-z0-9-]+$/`
  - every confusable exists and isn't its own id
  - each `ja` has exactly one `＿＿`
  - `pieces.join("") === fullSentence(ex)`
  - 3–5 pieces, with exactly one equal to `answer`
  - no shared meaning token with another grammar pattern, using the same token helper as kanji/vocab
  - every kanji in `fullSentence` has a `lookupKanji` entry
- [ ] **Step 2: Write the failing question tests** with a fixture of 6 grammar items, where `nagara`'s confusables are `["tsutsu"]` and `tsutsu.examples[0].answer === "つつ"`:
  - `grammar options include the confusable answer first`: with `rand = () => 0` the options contain `"つつ"`, have length 4, and contain the right answer once.
  - `grammar options never repeat the answer`: a confusable whose answer equals the right one is skipped, so options are unique.
  - `order tiles are a shuffle, never already in order`: `rand` that would return identity order still yields `tiles.join("") !== fullSentence`, and the tiles are the same multiset as `pieces`.
  - `choice on grammar uses meaning or prompt only`.
- [ ] **Step 3:** Run `npx vitest run src/lib/question.test.ts src/data/data.test.ts`. Expected: they fail.
- [ ] **Step 4: Implement** the `grammar` and `order` cases plus the grammar branch of `choice`.
  - **Grammar options:** candidate answers are the confusables' example answers, then the answers of shuffled same-level grammar patterns, then the answers of all grammar patterns. Drop any equal to the right answer, dedupe, take 3, shuffle with the answer.
  - **Order tiles:** reshuffle up to 10 times while the joined tiles equal the sentence. If that still fails, swap the first two differing tiles.
- [ ] **Step 5:** Run `npm run check`. Expected: it passes.
- [ ] **Step 6:** Commit with `git commit -m "Grammar: data checks and question building"`.
